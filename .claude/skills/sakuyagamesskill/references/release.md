# 本番公開とわいわいタウン掲載

## 本番公開

順番どおりに進める。★ は利用者の手が要る作業（押す場所まで書いて頼む）。

1. **公開前チェックリスト**（`kit-rules.md` の「公開前の確認」）を playtest と実機で通す
2. **PR を作ってマージ**（作業ブランチ → main、squash）
3. ★ **GitHub Pages を有効にする**: リポジトリの Settings → Pages → Branch を `main` / `/(root)` にして Save。
   Custom domain に `xxx.naoblock.jp` を入れ、Enforce HTTPS にチェック（リポジトリの `CNAME` と同じ値）
4. ★ **DNS**: naoblock.jp の DNS に `xxx` の CNAME レコード（値 `naonao1971.github.io`）を足す。反映に数分〜1時間
5. ★ **共通ランキングのスプレッドシート**（「score」）の `_games` シートに1行足す:

   | gameId | タイトル | シート名 | 総合に含める | スコア上限 |
   |---|---|---|---|---|
   | xxx | 咲耶XXX | xxx | TRUE | `maxScore` と同じ値 |

   行が無くても初回の登録でシートはできるが、総合ランキングの名前と上限のチェックはこの行で決まる
6. **公開 URL で1回遊び、ランキングに登録できるか**を利用者に確かめてもらう
7. ★ **OGP の確認**: X の投稿画面に URL を貼って、カードに ogp.png・タイトル・説明文が出るか見てもらう
8. 既存3作の `index.html` の姉妹作リンク（遊び方の欄）に新作を足す（任意。別の PR）

## わいわいタウン掲載

わいわいタウン（https://waiwai.town/ ・β）は、登録なしで遊べる作品を集めたサイト。CNP の二次創作ゲームも載っている。
この環境からはサイトを開けないので、**登録画面の項目は利用者に画面を見てもらって合わせる**。
初めて載せるときは、登録画面のスクリーンショットをもらい、下の「登録画面の項目」を埋めてこのファイルに書き足しておく（次の新作から聞かずに済む）。

### 掲載用パック（先に全部作って渡す）

| 項目 | 作り方 |
|---|---|
| 作品名 | 日本語名（例 咲耶ジャンプバグ） |
| URL | 本番の公開 URL（raw.githack ではなく `https://xxx.naoblock.jp/`） |
| ひとこと紹介（〜40字） | 企画書の「ひとことで」を縮める |
| 紹介文（200〜400字） | 何をするゲームか → 見どころ（CNP 11体・ランキング・総合ランキング）→ 遊べる環境（スマホ横持ち・PC、登録なし） |
| 遊び方・操作 | 企画書の操作表を、PC とスマホに分けて箇条書き |
| サムネイル | `ogp.png`（1200x630）。正方形が要るなら `icon-512.png` |
| スクリーンショット | playtest の画面写真から、タイトル・プレイ中・クリアの3枚（HUD と CNP が見えるもの） |
| タグ・ジャンル | 元ネタのジャンル（シューティング／アクション／迷路 など）、CNP、二次創作、レトロ、ブラウザゲーム |
| 権利表記 | 「本作は CryptoNinja / CryptoNinja Partners / Nouns の非公式ファンアートです」（kit のフッターと同じ） |
| 作者 | 利用者の名前と X の ID（聞いて入れる） |
| 姉妹作 | 咲耶スクランブル / 咲耶Nounラリー / 咲耶ジャンプバグ の URL |

パックは Markdown にまとめて、リポジトリの `docs/WAIWAI.md` にも置く（後から直せるように）。
