# 咲耶シリーズ 新作づくりガイド（AI に読ませる用）

咲耶シリーズ（CNP の二次創作・レトロアーケード風ブラウザゲーム）の新作を、咲耶ゲームkit（sakuya-kit）を使って AI（Claude・Codex など）と一緒に作るための1枚ものの手順書です。
昔のレトロゲームのタイトルと簡単な要件を伝えると、AI が質問しながら構成を固め、プロトを作り、公開とわいわいタウン掲載まで案内します。

---

## はじめに（人が読む部分）

### 用意するもの

- GitHub のアカウントと、新作用の空のリポジトリ（名前は例 `SakuyaXxx`）
- 公開先（GitHub Pages。独自ドメインを使うなら DNS を触れること）
- 作りたいゲームのイメージ: 元ネタのレトロゲーム1〜3本と、やりたいこと
- （あれば）キービジュアル（横長の絵）、クリア／ゲームオーバーの動画（mp4）
- Google アカウント（自分用のランキングを置くスプレッドシートと Google Apps Script に使う）

### AI への読ませ方

| 使うもの | 読ませ方 |
|---|---|
| **Claude Code**（CLI・Web・デスクトップ） | 新作のリポジトリに sakuya-kit を clone するか、sakuya-kit リポジトリを一緒に開く。sakuya-kit の `.claude/skills/sakuyagamesskill/` が自動で読まれる。無い環境では「`docs/GAME-GUIDE.md` を読んで、その手順で進めて」と伝える |
| **claude.ai（チャット）** | Settings → Capabilities → Skills に sakuyagamesskill の zip を取り込む。または、このファイルを添付して「この手順で進めて」と伝える |
| **Codex**（CLI・Web） | 新作のリポジトリの直下に、このファイルを `AGENTS.md` という名前でコピーして置く（Codex は `AGENTS.md` を自動で読む）。または最初に「`docs/GAME-GUIDE.md` を読んで従って」と伝える |
| **その他の AI（ChatGPT など）** | このファイルを添付するか貼り付けて、「この手順で進めて」と伝える |

### 最初のひとこと（例）

> バルーンファイトとディフェンダーを混ぜたような咲耶シリーズの新作を作りたい。スマホで片手で遊べるものがいい。

### ランキングは作者ごと

ランキングは**作者ごとに自分のスプレッドシートと GAS を持ちます**（手順は下の「ランキング」）。
公式の総合ランキング（咲耶スクランブル・Nounラリー・ジャンプバグなど）は公式タイトルだけで集計するので、
自分のタイトルはそこには載りません。自分の GAS では、自分のタイトル同士の総合ランキングが作れます。

sakuya-kit に機能を足したいときは、sakuya-kit リポジトリへの Pull Request で運営者（naonao1971）に相談してください。

## AI への指示（ここから下は AI が従う）

あなたは咲耶シリーズの新作づくりを手伝う。利用者は開発者ではない前提で、次の原則を守って進める。

### 原則

1. **段階ごとに区切り、利用者の OK をもらってから次へ進む。** 各段階の終わりに「決まったこと／次にやること」を短く出す
2. **質問は1回に4つまで。** 選択肢で聞き、おすすめを先頭に「（おすすめ）」付きで置く。細部は聞かずに既定値で進め、何を既定にしたかだけ伝える
3. **専門用語を避ける。** 確認してほしいことは「どこを押して、何が起きれば OK か」で書く
4. **共通部分は必ず sakuya-kit を使う。** コントローラー、ポーズ、スタート、縦持ち案内、スコア登録、ランキング、CNP、演出動画と結果画面、全画面、効果音とミュート、シェアを自前で書かない（下の「sakuya-kit のルール」）
5. **決まったことはリポジトリの `docs/PLAN.md` に書き足す。** 会話が途切れても、そこから再開する
6. **自分の環境でできないこと**（リポジトリの作成、外部サービスへのログイン、スプレッドシートの操作など）は、押す場所まで書いた手順で利用者に頼む

### 段階 0: 受け付け

最初の言葉から、元ネタのレトロゲーム・やりたいこと・すでに決まっている名前や素材を拾う。
元ネタごとに下の「レトロゲームの読み替え表」を引いて**借りどころ**を示し、
複数の元ネタは「A の操作 × B の目的」のような組み合わせ案を2〜3個出して選んでもらう。
表に無いタイトルは、知っている範囲で同じ形（中心の遊び・操作・kit の設定）に書き起こす。

### 段階 1: ヒアリング

下の「質問票」を上から順に、まだ決まっていないものだけ聞く（最大4ラウンド）。各ラウンドの後に、決まった内容を2〜3行で復唱する。

### 段階 2: 企画書 → 承認

下の「企画書のひな形」で1ページにまとめて見せ、OK をもらう。
必ず決めること: 日本語名・英字の主題と副題・`gameId`・公開 URL・操作・クリア条件・スコアの付け方と上限の目安。

### 段階 3: リポジトリの用意

1. 利用者に空のリポジトリを作ってもらう（名前の案を出す）。AI からリポジトリに書き込むための設定（GitHub アプリの追加など）が要る環境なら、その手順も渡す
2. sakuya-kit を clone する: `git clone https://github.com/naonao1971/sakuya-kit`
3. `sakuya-kit/.claude/skills/sakuyagamesskill/assets/starter/index.html` を新作の `index.html` として置き、企画書の値（`gameId`・名前・操作）を入れる
4. `docs/PLAN.md` に企画書、`README.md` に「sakuya-kit を使っている／遊び方／操作」を書く
5. 作業ブランチを切って push する
6. 自分用のランキング（GAS）がまだ無ければ、下の「ランキング」の手順を渡して用意してもらい、URL を `gasUrl` に入れる

### 段階 4: プロト（遊べる最小版）

**目的は「中心の遊びが面白いか」を早く確かめること。** 絵は仮でよい（canvas の図形と `kit.cnp` の絵）。

- 入れるもの: 自機の操作、中心の遊び1つ、ミスとゲームオーバー、スコア、クリア（またはエンドレスの終わり方）
- 入れないもの: 演出動画、凝った背景、OGP、細かい調整
- 動かして確かめる（下の「テスト」）。画面写真を自分で見て、崩れや読めない文字が無いかを確かめてから渡す
- push して、スマホで遊べる URL を渡す: `https://raw.githack.com/<owner>/<repo>/<ブランチ>/index.html`
- 感想の質問は「速さ／難しさ／操作のしやすさ／もっと欲しいもの」の4つまで。直して、また URL を渡す。
  「中心の遊びがこれでよい」と言われるまで繰り返す

### 段階 5: 仕上げ

遊びに近いものから順に入れ、ひとつ入れるごとにテストと URL で確認してもらう。

1. ステージ・敵・難易度の流れ、CNP 11体の出し方（全員そろえるとボーナス、など）
2. HUD（`kit.hud`）、効果音（定番は `kit.sfx`、固有の音だけ自前）、BGM（任意）
3. 結果画面の飾り（`resultScreen.decorate`：ボーナスの内訳・救出した CNP）
4. 演出動画（任意。mp4 を `cutscenes` に渡すだけ）
5. シェア（`share`。文言とハッシュタグ、1200x675 のカード絵は任意）
6. スコアの上限: 理論上の最高点を計算し、少し上の切りのよい数を `maxScore` にする

### 段階 6: タイトル・OGP・アイコン

- キービジュアル（横長）をもらう。無ければタイトル画面の canvas を書き出して仮に使う
- 次のどちらかで、ogp.png・アイコン・favicon・manifest.json・`<head>` を作る
  - スクリプト（Node と Playwright がある環境）:
    ```
    node sakuya-kit/.claude/skills/sakuyagamesskill/scripts/make-assets.mjs --game . --kit sakuya-kit \
      --visual <絵> --title "SAKUYA XXX" --subtitle "- XXX -" --name-ja "咲耶XXX" \
      --desc "説明文（60〜90字）" --url "https://xxx.example.com/"
    ```
  - ブラウザのツール: `sakuya-kit/tools/ogp.html` を開き、入力して書き出す（利用者に操作してもらう）
- 独自ドメインなら `CNAME` にドメインを書く

### 段階 7: 本番公開

1. 下の「公開前チェックリスト」を、テストと利用者の実機で通す
2. 作業ブランチを main にマージする
3. 利用者に頼む: GitHub の Settings → Pages → Branch を `main` / `/(root)` にして Save。独自ドメインなら Custom domain に入れて Enforce HTTPS
4. 利用者に頼む: 独自ドメインなら DNS に CNAME レコード（値 `<owner>.github.io`）を足す
5. 利用者に頼む: 自分のランキングのスプレッドシートの `_games` シートに行を足す（下の「ランキング」）
6. 公開 URL で1回遊び、ランキングに登録できるかを確かめてもらう
7. X の投稿画面に URL を貼り、カードに ogp.png・タイトル・説明文が出るかを確かめてもらう

### 段階 8: わいわいタウン掲載と告知

わいわいタウン（https://waiwai.town/ ・β）は、登録なしで遊べる作品を集めたサイトで、CNP の二次創作ゲームも載っている。
登録（ログインと送信）は利用者が行う。AI は掲載用のパックを作り、登録画面の入力を一緒に進める。
登録画面の項目が分からないときは、画面のスクリーンショットをもらって合わせる。

| 掲載用パックの項目 | 作り方 |
|---|---|
| 作品名 | 日本語名 |
| URL | 本番の公開 URL（raw.githack ではなく） |
| ひとこと紹介（〜40字） | 企画書の「ひとことで」を縮める |
| 紹介文（200〜400字） | 何をするゲームか → 見どころ（CNP 11体・ランキング）→ 遊べる環境（スマホ横持ち・PC、登録なし） |
| 遊び方・操作 | 企画書の操作表を PC とスマホに分けて箇条書き |
| サムネイル | `ogp.png`（1200x630）。正方形が要るなら `icon-512.png` |
| スクリーンショット | タイトル・プレイ中・クリアの3枚（HUD と CNP が見えるもの） |
| タグ・ジャンル | 元ネタのジャンル、CNP、二次創作、レトロ、ブラウザゲーム |
| 権利表記 | 「本作は CryptoNinja / CryptoNinja Partners / Nouns の非公式ファンアートです」 |
| 作者 | 利用者の名前と X の ID |
| 姉妹作 | 咲耶スクランブル https://sakuya.naoblock.jp/ ／ 咲耶Nounラリー https://rally.naoblock.jp/ ／ 咲耶ジャンプバグ https://jumpbug.naoblock.jp/ |

パックはリポジトリの `docs/WAIWAI.md` にも置く。最後に X の告知文を3案（見どころ／CNP 11体／ランキング）作る。

## 質問票

### ラウンド 1: 遊びの芯
1. 元ネタから借りるもの（読み替え表の「借りどころ」から2〜3個）
2. 1プレイの長さ: 3分くらい（おすすめ）／1分で終わる短いもの／10分くらいのステージ制
3. 終わり方: ゴールしたらクリア（おすすめ）／エンドレス／制限時間
4. CNP 11体の役割: 拾って集める（おすすめ）／助け出す／仲間として戦う／ボーナスとして出る

### ラウンド 2: 操作
1. スマホの移動: 左半分のスティック（おすすめ）／canvas のどこでもスティック（迷路向け）／傾き（ジャイロ）
2. ボタン: 1つ（おすすめ）／2つ
3. 自動連射: いる（撃つゲームならおすすめ）／いらない
4. 難しさ: 最初はやさしく、だんだん難しく（おすすめ）／最初から歯ごたえ

### ラウンド 3: 見た目と名前
1. 日本語名: 「咲耶〇〇」の形で2〜3案
2. 英字の主題と副題: 例 `SAKUYA SCRAMBLE` / `- RESCUE 11 CNP -`
3. 世界観・ステージ: 元ネタと咲耶の組み合わせから2〜3案
4. 絵と動画: キービジュアルと、クリア／ゲームオーバーの動画を用意するか（後からでもよい）

### ラウンド 4: 公開
1. 公開 URL
2. リポジトリ名
3. ランキングの用意: 自分の GAS をもう持っている（URL を聞く）／これから作る（段階 3 のあとに手順を渡す）
4. わいわいタウンに載せるか: 載せる（おすすめ）／あとで

`gameId` は英小文字（例 `balloon`）で AI から案を出して確認だけ取る。あとから変えない。

## sakuya-kit のルール

咲耶ゲームkit（リポジトリは sakuya-kit：https://github.com/naonao1971/sakuya-kit）は、全タイトル共通の部品をまとめたフレームワーク（共通の土台）。ビルドは不要（素の ES Modules）。
詳しい設定は sakuya-kit の `README.md`、動く最小例は `demo/index.html`。

### 大原則

1. **共通部分は kit に任せる。** 足りない機能はタイトル側に書かず、kit に足す（sakuya-kit への Pull Request）
2. **kit は版を固定して読む。** `https://cdn.jsdelivr.net/gh/naonao1971/sakuya-kit@0.6.0/kit.js` と同じ版の `kit.css`。`@latest` や `@main` は使わない
3. **見た目で変えてよいのは色トークンだけ。** `kit.css` の後に `:root { --gold: ...; }`。ボタンの寸法・配置・フォントは変えない。canvas の色は `kit.retro.colors`
4. **タイトル側に書くのは `onStart` / `update` / `render` と、そのゲームにしかない描画・音・演出だけ**

### 書き方の要点

```js
import { createKit } from "https://cdn.jsdelivr.net/gh/naonao1971/sakuya-kit@0.6.0/kit.js";

const kit = createKit({
  gameId: "xxx",                       // ランキングのシート名。あとから変えない
  title: "SAKUYA XXX", subtitle: "- XXX -",   // <title> の「主題 ─ 副題」と同じ値
  gasUrl: "https://script.google.com/macros/s/<自分の GAS の ID>/exec",   // 下の「ランキング」で作る
  overall: false,                      // 自分のタイトルが1本だけの間は総合タブを出さない
  cnp: true,
  lives: { start: 3, extendEvery: 20000 },
  maxScore: 60000,                     // _games のスコア上限と同じ値
  controls: {
    stick: true,
    buttons: [{ id: "fire", label: "X", keys: ["KeyX"], primary: true, onPress: () => {} }],
    autoFire: { interval: 10, onFire: () => fire() },
  },
  cutscenes: { clear: { src: "assets/clear.mp4" }, gameOver: { src: "assets/gameover.mp4" } },
  resultScreen: { decorate: (ctx, { kind, rect, result, playing }) => {} },
  share: { when: "always", url: "https://xxx.example.com/", text: (r) => `咲耶XXX スコア ${r.score}` },
  onStart() { /* 1プレイ分の状態を初期化 */ },
  update(kit) { /* 60Hz 固定。プレイ中かつ非ポーズのときだけ呼ばれる */ },
  render(ctx, kit) { /* 毎フレーム。kit.phase（title / playing / over）で描き分ける */ },
});
window.kit = kit;   // テストが読む。消さない

// 1プレイの終わりに必ず呼ぶ
kit.gameOver({ cleared: true, progress: 100 });
```

- 移動は `kit.input.axis()`（キー・スティック・ジャイロの合成、各 -1..1）。ボタンの押下は `kit.input.buttons[id]`
- スコア・残機・チェックポイント・CNP の回収・HUD は `kit.score` / `kit.lives` / `kit.checkpoint` / `kit.cnp.run` / `kit.hud` を使う。
  HUD の位置は全タイトル共通（左上スコア、上段中央ロスター、右上残機・ゲージ）
- CNP は `kit.cnp.chars`（11体、`ch.no` は1始まり）と `kit.cnp.draw(ctx, ch, x, y, size)`。回収は `kit.cnp.run.collect(ch.no)`
- 結果画面と演出動画は kit が描く。動画は `cutscenes` に渡すだけで、再生・スキップ・ジングル・結果画面は書かない
- 傾き操作は既定で使わない。使うときは `controls.gyro`（自前で deviceorientation を扱わない）
- ジャンプ等をスティックの上や画面右半分でも押せるようにするときは `stickUpButton` / `rightHalfButton`
- キーの P（ポーズ）・M（音）・V（自動連射）・Enter / Space（スタート）は変えない
- 定番の効果音は `kit.sfx.pickup()` などを使い、同じ意味の音はタイトル間でそろえる
- canvas は 960x540（横持ち前提）。サイドパネルが要るなら canvas を横に広げて中に描く
- タイトル画面は `kit.retro.titleText(主題, 副題)`、走査線 `kit.retro.crt()` は背景と地形だけに敷く
- 権利表記（非公式ファンアート）は kit のフッターのまま残す

### ランキング（作者ごとに自分で用意する）

ランキングは作者ごとに、自分のスプレッドシートと GAS を1組持つ。複数のタイトルを作るなら、同じ1組を全タイトルで共有する。
公式タイトル（naonao1971 の作品）の GAS は使わない。

**用意の手順**（利用者が行う。AI は押す場所まで書いて渡す）

1. Google スプレッドシートを新しく作る（名前は例「咲耶ランキング」）
2. 拡張機能 → Apps Script を開き、sakuya-kit の `gas/apps-script.gs` の中身を丸ごと貼り付けて保存
3. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」、実行するユーザー「自分」、アクセスできるユーザー「全員」→ デプロイ（初回は権限の許可を求められる）
4. 発行された URL（`https://script.google.com/macros/s/…/exec`）を `createKit({ gasUrl })` に入れる
5. 最初のスコアが届くと `_games` シートができ、公式3作（scramble / jumpbug / rally）の行が自動で入る。**この3行は消す**
6. 自分のタイトルの行を足す（または自動で足された行を直す）:

   | gameId | タイトル | シート名 | 総合に含める | スコア上限 |
   |---|---|---|---|---|
   | xxx | 咲耶XXX | xxx | TRUE | `maxScore` と同じ値 |

- スコアは `gameId` ごとのシートに入る。スコア上限を超える記録は GAS が断る
- 自分のタイトルが2本以上になったら、`overall: false` を外すと、自分のタイトル同士の総合ランキングのタブが出る
  （各タイトルの「自己ベスト ÷ 1位 × 1000」の合計）
- `gas/apps-script.gs` が新しくなったら、貼り直して「デプロイを管理」→ 編集 → 新バージョン（URL は変わらない）
- 公開後にスコアの付け方を大きく変えない（ランキングの比較が崩れる）

## テスト

Node と Playwright（Chromium）がある環境では、自動プレイテストを回す。

```
node sakuya-kit/.claude/skills/sakuyagamesskill/scripts/playtest.mjs --game . --kit sakuya-kit --out ./playtest-out
```

- PC（開始・プレイ・一時停止・ゲームオーバー・クリア）とスマホ横持ち（スタート・スティック・縦持ちの案内）を通し、画面写真を書く
- CDN の kit は手元の clone に、ランキングは偽物に差し替えるので、外に出られない環境でも動く
- 最後の行が `OK` ならエラーなし。画面写真は必ず目で確かめる
- テストのブラウザでは H.264 の動画が流れないことがある。動画は実機で確かめてもらう

テストを回せない環境では、ブラウザで開いて開発者コンソールにエラーと `sakuya-kit` の警告が無いかを利用者に確かめてもらう。
